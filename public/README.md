# Same Word · 双人同词相遇（联网版）

一个不需要数据库、不需要第三方 npm 依赖的双人实时联机小游戏。

- 服务端：Node.js 原生 HTTP + 原生 WebSocket（自己实现 RFC 6455 子集）
- 前端：单页 HTML，内嵌全部 CSS / JS
- 房间：内存房间，服务端权威判定，最多 2 人
- 同步：WebSocket 实时推送，无需刷新
- 断线：自动重连；同一标签页刷新后自动回到原房间
- 隐私：任何一方提交后，服务器只告诉对方「已提交」，不会提前下发词语

## 2. 本机运行

要求：Node.js 20 或更新版本。

```bash
cd same-word-online
node server.js
```

打开：

```text
http://localhost:3000
```

没有 `npm install` 步骤，因为项目没有第三方依赖。

健康检查：

```text
http://localhost:3000/healthz
```

也可以使用：

```bash
npm start
```

## 3. 同一 Wi-Fi 联机

1. 在运行服务器的电脑上执行 `node server.js`。
2. 终端会打印类似：

   ```text
   局域网： http://192.168.1.109:3000
   ```

3. 两台设备都访问这个局域网地址，不要用 `localhost`。
4. Windows 如果弹出防火墙提示，请允许 Node.js 访问专用网络。
5. 创建房间后复制邀请链接，发给另一台设备即可。

> 注意：页面上的「复制邀请链接」使用的是你当前浏览器地址栏的域名。如果你是用 `localhost` 打开的，复制出来的链接只在本机有效。想分享给同一 Wi-Fi 下的另一台设备，请先用局域网 IP 打开页面。

## 4. 部署到公网

这是一个普通 Node Web Service，监听 `process.env.PORT`，支持 WebSocket 升级。可部署到 Render、Railway、Fly.io、自己的 VPS 等。

### Render / Railway 通用配置

- Runtime：Node
- Build Command：留空，或 `npm install`（没有依赖，执行也无害）
- Start Command：`node server.js`
- Health Check Path：`/healthz`
- 实例数量：1

### Docker

```bash
docker build -t same-word-online .
docker run -p 3000:3000 same-word-online
```

如果使用 Nginx / Caddy 等反向代理，请确保转发 WebSocket 升级请求（`Upgrade`、`Connection` 头），并且把 `/ws` 一并代理到 Node。公网建议使用平台提供的 HTTPS；页面会自动使用 `wss://` 连接。

### 安全提示

- 房间码就是这间小屋的钥匙，不要把正在进行的房间链接公开贴出。
- 服务端不设账号系统，只做两人房间；重要隐私内容不要写进游戏词语。
- 单实例部署即可。若要多实例水平扩容，需要把内存房间迁移到 Redis 等共享存储，并处理 WebSocket 粘性会话。

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口，云平台通常会自动注入 |
| `HOST` | `0.0.0.0` | 监听地址 |

## 5. 房间与数据说明

- 房间状态只保存在服务器内存里，服务器重启会清空所有房间。
- 房间码是 6 位大小写字母 + 数字，实际查找不区分大小写。
- 一局固定 2 人，第三个人会被拒绝。
- 空房间 30 分钟后清理；创建超过 12 小时的房间也会清理。
- 玩家网络断开后，座位会保留一段时间，重新连回同一标签页即可恢复。
- 刷新页面会通过 sessionStorage 里的凭证自动 `resume` 原座位。
- 关闭标签页后，新标签页没有这份本地凭证，无法自动找回座位；这是为了区分同一浏览器里的两个玩家。
- 服务端不记录账号、不接入第三方统计，也不会把词语写入数据库。

## 6. 玩法流程

1. 两个人各自盲写一个词。
2. 都提交后同时揭晓。
3. 完全一样 → 相遇成功。
4. 不一样 → 双方分别判断是否同义：
   - 任意一人选「否」→ 立即进入下一轮；
   - 两人都选「是」→ 相遇成功。
5. 下一轮基于上一轮的两个词继续联想。
6. 成功页可以选择「再来一局」，需要两个人都点一次。
7. 任意一人退出房间，房间会关闭，另一端会实时收到提示。

所有判定都由服务端执行，客户端只提交意向，不能自行修改结果。

## 7. 常见问题

### 另一台设备打不开

- 确认两台设备在同一个 Wi-Fi。
- 使用终端打印的局域网 IP，而不是 `localhost`。
- 检查 Windows 防火墙是否放行 Node.js。
- 云服务器检查安全组 / 防火墙是否放行对应端口。

### 页面显示「连接断开」

- 页面会自动重连，并显示重连状态。
- 如果服务器已停止，请重新运行 `node server.js`。
- 如果是公网部署，检查反向代理是否支持 WebSocket。

### 刷新后回不到房间

- 只有同一个标签页内刷新才会自动恢复座位。
- 关闭标签页后重新打开，会被当作新玩家；如果房间已满，就无法加入。
- 这是为了避免同一浏览器两个标签页共用同一个身份。
